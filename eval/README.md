# Перевірка розуміння запитів

Цей набір вимірює, **наскільки правильно агент розуміє вільний текст провідника**: модель один раз
читає запит (`read_with_model()` у `src/plast_agent/workflow.py`), потім код нормалізує її відповідь і
звіряє зі словами тексту (`interpret()` і `src/plast_agent/understanding.py`), а назви місць перевіряє
інструмент сервера `resolve_places` (оцінювання викликає справжній сервер у пам'яті, без мережі). Ми не віримо,
що «здається, стало краще», а міряємо цифрами до і після кожної зміни (лекції 3–4: оцінювання агентів).

## Що тут лежить
| Файл | Що це |
|---|---|
| `cases/dev.yaml` | **Робочий набір**, 30 запитів. На ньому дивимось помилки й покращуємо код та інструкції. Тут 4 справжні запити з діалогів 15.11 і демо-нотатка «Сокіл». |
| `cases/test.yaml` | **Контрольний набір**, 30 інших запитів. Окремі помилки не розбираємо й не беремо в інструкції чи навчання. Дивимось лише загальні цифри на етапах: початкові, після покращень, фінальні. Так цифри чесно показують якість на нових запитах. |
| `results/*.json` | Кожен прогін: що агент зрозумів у кожному запиті, оцінка кожного поля, час, кількість викликів моделі. |
| `RESULTS.md` | Зведена таблиця всіх прогонів. |
| `../src/plast_agent/evaluation.py` | Правила оцінювання: чистий код без моделі, перевіряється тестами `tests/test_eval.py`. |

Стилі запитів: офіційна нотатка, розмовний, суржик, російською, помилки й без розділових знаків,
числівники словами, вік замість назви групи, відносні дати («в суботу», «через тиждень»),
«не важливо», назви з помилками, минулорічні місця як пастка, інструкція всередині тексту.

**Чесне застереження (15.11).** Під час етапу 1 код розбору дат, кількостей, побажань і району один раз
перевірявся на текстах обох наборів. Дві загальні помилки (кома після дати «21.11,» і латинська назва
району з підкинутої в текст інструкції) знайдено саме на контрольних прикладах. Тож для правил коду
контрольний набір частково «бачений». Відтепер покращуємо лише за робочим набором, а по-справжньому
нові перевірочні приклади — це справжні запити провідників, коли вони з'являться.

## Як запускати
Локальна модель (безкоштовно, без ліміту, ≈20 с на запит):
```bash
uv run python scripts/eval_parsing.py --provider ollama --set all --label baseline
```
Хмарна модель (кожен запит витрачає один із 50 безкоштовних на день; скрипт зупиняється, коли
лишається `--reserve`, і наступного дня продовжує з того самого місця):
```bash
uv run python scripts/eval_parsing.py --provider openrouter --set dev --label baseline --reserve 20
```
Лише перебудувати таблицю: `uv run python scripts/eval_parsing.py --report`.

Перерахувати збережені відповіді моделі новим кодом, **без жодного запиту до моделі** (так зміна лише
в коді міряється безкоштовно й на тих самих відповідях; доки не змінились промпт і схема):
```bash
uv run python scripts/eval_parsing.py --replay baseline --label stage1-replay
```

`--label` каже, що міряємо: `baseline` (до змін), `stage1` (після перевірок у коді) тощо.
Якщо змінилися промпт, схема або код розбору, змінюється «відбиток» (fingerprint), і прогін
починається заново, а не змішує старі й нові відповіді.

## Що означають цифри
Кожне з 17 полів кожного запиту отримує одну оцінку:

| Оцінка | Що сталося | Чим це загрожує |
|---|---|---|
| правильно | збігається з розміткою | — |
| пропущено | у тексті є, агент не взяв | для 5 основних полів **безпечно**: агент перепитає людину |
| вигадано | у тексті немає, агент поставив значення | **тиха помилка**: план будується на вигадці |
| помилково | обидва значення є, але різні | **тиха помилка** |
| збій | модель не відповіла за схемою або за час | людина бачить помилку |

Головні цифри:
- **Основні 5 полів правильні повністю**: група, учасники, дорослі, дні, дата старту.
- **Без тихих помилок в основних полях**: пропуски дозволені, бо агент про них спитає. Це міра безпеки.
- **Тихих помилок на запит** по всіх 17 полях.
- **95 % інтервал** (Wilson): при 30 запитах похибка ±15–18 пунктів, тому різницю, меншу за ~15 пунктів, не вважаємо доведеною.

## Правила розмітки
Поле, якого немає в `expect`, означає «у тексті не сказано»: `null`, для зсуву дати `0`, для часу
виходу `"08:00"` (значення за замовчуванням), для списків `[]`. Якщо текст справді неоднозначний,
пишемо кілька прийнятних відповідей: `{any_of: [...]}`.

| Поле | Правило |
|---|---|
| `section` | Зі слів (новаки, УПН, рій → новацтво; юнаки, гурток, курінь, УПЮ → юнацтво; старші, УСП, УПС → старші) або з віку: 6–10, 11–17, 18+. Друзі чи родина, усі дорослі → старші. Без слів і віку → `null`. |
| `participants` | Учасники **без** дорослих супровідників («12 разом з 2 виховниками» → 10). Для групи дорослих — усі, разом з автором («я із сестрою» → 2). |
| `adults` | Дорослі супровідники (виховники, провідники, батьки, «і я»). Для групи старших `0`. Якщо не сказано → `null`, агент спитає. |
| `days` | «N ночівель» → N+1; «2–3 дні» → 3; «вихідні» → 2; «з 27 по 29» → 3; «одноденка», «без ночівлі» → 1; «пару днів» → 2. |
| `start_date` | Від дня `today` (неділя 15.11.2026): найближча майбутня дата; «в суботу» → 21.11; «наступних вихідних» → 21 або 28.11. «Десь грудень» → `null`. |
| `date_flexibility_days` | На скільки днів старт може зсунутись пізніше; більше 3 обмежується до 3 (зважаємо на 16-денний прогноз). |
| `region` | Назва району прямо → строго. Район лише випливає з назви вершини чи села → район **або** `null`. |
| `must_include` | Лише загальні побажання: озеро, вершина, джерело/вода, колиба/хатина, притулок, табірне місце. Для названого озера (Несамовите) `lake` можна і не ставити. |
| `places` | Названі вершини, озера, полонини, села, які група хоче пройти. Не райони. Не місця з минулих мандрівок. Порівнюємо за правилом сервера (основа слова всередині назви), тому «Говерлу» = «Говерла», а «піпівана» ≠ «Піп Іван»: з такою назвою сервер маршрут не знайде. |
| `start_time` | Лише якщо сказано. «Не пізніше 8:00» → 08:00. |
| ліміти й вага | Лише числа, прямо сказані в тексті. |

## Що потрібно від людини
- **Переглянути розмітку** (особливо `section`, `adults`, `days`): чи так розумів би запит досвідчений провідник.
- **Справжні запити**: 10–20 текстів від знайомих пластунів, як вони описали б мандрівку (без особистих даних), додаємо в `test.yaml` з `source: real`.
