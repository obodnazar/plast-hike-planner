# Сценарій захисту (наживо, 10–15 хв)

Мета: показати 9 обов'язкових пунктів із завдання й самостійно пояснити кожен крок. Під час захисту AI використовувати не можна, тому нижче є все, що треба сказати, і відповіді на ймовірні питання.

---

## 0. Підготовка

**За 1–3 дні до захисту** (прогнози в fixtures діють 16 днів):
```bash
uv run python scripts/record_weather.py        # свіжі прогнози для всіх 121 маршрутів (~3 хв)
```
- У нотатці `Запити/Мандрівка гуртка Сокіл.md` зміни дату старту на день у новому вікні прогнозу, наприклад 28 листопада.
- Зроби повну репетицію (див. розділ 1). Перевір, що план проходить, а погода дає «високий ризик → перенесення дати» або інший цікавий сценарій. Якщо погода всюди спокійна, цикл через погоду не спрацює. Тоді для демонстрації циклу постав у запиті жорсткіший ліміт (наприклад, 8 км на день): спрацює цикл через правила.

**За годину до захисту:**
```bash
uv run python scripts/reset_demo.py            # прибрати старі плани й рядки агента
uv run check-obsidian                          # Obsidian відповідає, 20 інструментів
uv run pytest -q                               # 25 тестів
```
- Obsidian відкритий на `demo-vault`, видно папки `Запити` і `Плани`.
- Два вікна терміналу в папці `plast-hike-planner`, шрифт великий.
- На OpenRouter лишилося ≥ 10 безкоштовних запитів (один прогін використовує 3–6; ліміт 50 на день спільний для всіх безкоштовних моделей).
- Закрий усе особисте: повідомлення, інші вкладки.

## 1. Сценарій по хвилинах

### 0:00–2:00 · Запуск і архітектура (обов'язкові пункти 1–2)

**Термінал 1:**
```bash
uv run plast-trail
```
Покажи в лозі: `121 routes`, `rules: DRAFT`, `weather mode: replay`, `serving MCP ... http://127.0.0.1:8770/mcp`.

> **Сказати:** «Це мій власний MCP-сервер. Він працює окремим процесом на своєму порту, а агент підключається до нього так само, як до будь-якого іншого MCP-сервера. Другий сервер — Obsidian: MCP-сервер, вбудований у плагін Local REST API. Агент на LangGraph підключається до обох через MCP-клієнт. Модель дає OpenRouter, безкоштовна Nemotron.»

Відкрий схему в `README.md` (розділ Architecture) і за 20 секунд пройди межі: агент тримає порядок кроків, модель лише вибирає, сервер рахує, Obsidian читає й пише нотатки.

### 2:00–5:00 · Obsidian у потоці агента (пункти 2–5)

Покажи в Obsidian нотатку-запит. Це звичайний текст, як його написав би провідник.

**Термінал 2:**
```bash
uv run plast-agent "Запити/Мандрівка гуртка Сокіл.md"
```
- **Крок 0:** `✓ obsidian ... 20 tools`, `✓ plast-trail ... 4 tools`. Це discovery: `initialize` + `tools/list` для обох серверів.
- **Крок 1:** `obsidian.vault_read(...)`. Це успішний виклик інструмента існуючого сервера.

> **Контракт `vault_read` (сказати коротко):** «Обов'язковий аргумент один: `path`, шлях до нотатки від кореня vault. За бажанням можна прочитати лише розділ нотатки (`targetType`/`target`). Повертає JSON: текст нотатки, frontmatter, теги, посилання й мітку версії. Побічних ефектів немає. Помилки: якщо нотатки немає — `isError` і "File not found"; неправильний ключ — HTTP 401; закритий Obsidian — немає з'єднання.»
>
> **Роль:** «Obsidian — це і вхід, і вихід агента. З нотатки беруться ліміти групи: 12 км на день і ночівля не вище 1600 м. Вони йдуть у `validate_hike_plan` і перекривають правила Пласту, коли суворіші. А наприкінці агент записує план назад у `Плани/` і додає посилання в запит.»

(Агент тим часом працює; переходь до наступного блоку, поки він іде.)

### 5:00–9:00 · Повний потік зі своїм сервером (пункти 6–8)

Коментуй кроки, які з'являються в терміналі:
1. **Крок 2 (LLM):** «модель перетворює вільний текст на поля»; покажи `max_km_per_day: 12`, `date_flexibility_days: 2`.
2. **Крок 3:** `find_routes`. Це єдиний пошуковий інструмент; він фільтрує 121 маршрут за правилами секції.
3. **Крок 4.1 (LLM):** модель вибирає маршрут і ночівлі. **Вона повертає лише id точок, а не кілометри.**
4. **Крок 5:** `validate_hike_plan` рахує кожен день сам; покажи км, набір висоти, години, прихід і захід сонця.
5. **Крок 6:** `assess_weather_risk`. Якщо ризик high, з'являються `проба дати ...`, і агент повертається на крок 4 з фактами.
6. **Крок 4.2:** модель змінює дату (або маршрут). Це і є зворотний зв'язок: результат інструмента змінює наступний крок.
7. **Кроки 7–9:** запаси, висновок, `vault_write` і `vault_append`.

Відкрий в Obsidian `Плани/Мандрівка гуртка Сокіл — план.md`: таблиця днів, погода, запаси, документи, розділ **«Як агент дійшов до цього плану»** з усіма спробами.

**Доказ, що інструментів ≥ 3 (пункт 7):** у кроці 0 видно `4 tools: find_routes, validate_hike_plan, assess_weather_risk, calculate_supplies`. За бажанням у терміналі 2:
```bash
uv run python scripts/smoke_server.py | head -8     # кожен інструмент з input/output схемою
```

**Один контракт і рішення (пункт 8): `validate_hike_plan`**
> «Вхід: `route_id`, секція, кількість учасників і дорослих, id місць ночівлі по порядку (N id дають N+1 день), дата, час старту й ліміти групи з Obsidian. На кожне поле є обмеження: шаблон `^r\d+$`, від 1 до 60 учасників, не більше 6 ночівель.
> Вихід: `valid`, дні з усіма числами, `violations`, і в кожного порушення є код, ліміт, фактичне значення, джерело правила й **конкретна порада, часто з кращим id точки**.
> Головне рішення: **модель вибирає, сервер рахує.** Модель не може вигадати кілометри, бо план складається лише з id. Друге рішення: помилка й "ні" — різні речі. Неправильний маршрут дає `isError` з кодом `ROUTE_NOT_FOUND`, а план, що порушує правила, — нормальна відповідь `valid: false`, з якою агент працює далі.»

### 9:00–11:00 · Збій існуючого сервера + режим без інтернету (пункт 9)

**Збій:** закрий Obsidian (Cmd+Q) і запусти агента ще раз:
```bash
uv run plast-agent "Запити/Мандрівка гуртка Сокіл.md"
```
Очікувано:
```
✗ Obsidian MCP is not reachable at https://127.0.0.1:27124/mcp/. Is Obsidian open with the demo vault and the Local REST API plugin enabled?
Без Obsidian агент не може прочитати запит, тому зупиняюсь. Нічого не змінено.
```
> «Помилку зловлено на етапі підключення, повідомлення каже, що робити, і нічого не змінено. Якщо Obsidian зникне саме перед записом, план збережеться в `out/`.»

Відкрий Obsidian назад. Запасні варіанти збою, якщо попросять:
- неправильний ключ: `OBSIDIAN_API_KEY=wrong uv run plast-agent "Запити/Мандрівка гуртка Сокіл.md"` → HTTP 401;
- неіснуюча нотатка: `uv run plast-agent "Запити/Немає.md"` → «Запит не знайдено… Наявні запити: …».

**Replay:** у лозі сервера видно `weather mode: replay`. Покажи файл `fixtures/open-meteo/r8613349_*.json`, де лежать справжній запит і справжня відповідь Open-Meteo.
> «У replay сервер бере записану відповідь і пропускає її через той самий парсер і ті самі пороги, що й живу. Готових відповідей у коді немає. Живий режим: `WEATHER_MODE=live uv run plast-trail`.»

### 11:00–15:00 · Питання й зміна вхідних даних

Див. розділ 2. Мінімум для захисту: **змінений валідний вхід, невалідний вхід і простеження одного значення**.

## 2. Заготовки для питань

### Змінити валідний вхід
У нотатці-запиті зміни один рядок і запусти агента:
- «**новацтво**, 8 дітей і 2 дорослі, **2 дні**, **Горгани**». Будуть інші маршрути, а ночувати можна лише в хатинах або на стоянках (правило новацтва).
- або «не більше **8 км** на день». Валідація відхилить план і запропонує точки ближче, тобто спрацює цикл через правила.

### Невалідний вхід
```bash
uv run python scripts/smoke_server.py | sed -n '/ERROR CASE/,$p'
```
Показує три помилки й порожній результат:
- `days=0` → помилка схеми, тіло інструмента не виконується;
- `route_id="r1"` → `ROUTE_NOT_FOUND`;
- ночівлі не по порядку → `WAYPOINT_ORDER`;
- «нічого не знайдено» → **не помилка**: `routes: []` і пояснення в `excluded`.

### Простежити значення від джерела до результату
**«11.0 км, 5.2 год і прихід 14:12 у дні 2»:**
1. Лінія маршруту `r8613349` береться з OpenStreetMap (relation 8613349) скриптом `build_dataset.py`. Профіль має точку кожні 250 м, висоти з SRTM.
2. Точки `w30` (стоянка, км 11.35) і `w56` (стоянка, км 22.35) — це об'єкти OSM у межах 300 м від стежки, з позицією на профілі (`data/routes.json`).
3. Модель вибрала ночівлі `["w30", "w56"]` (видно в кроці 4).
4. `validate_hike_plan` рахує: 22.35 − 11.35 = **11.0 км**; набір **1087 м** — сума підйомів профілю між цими км (ігноруються коливання менше 10 м).
5. Час: 11.0 / 4 км/год + 1087 / 450 м/год = 2.75 + 2.42 = **5.2 год** (правило Ленгмюра, `rules.yaml → pace`). З привалами: 5.2 × 1.2 = 6.2 год; 08:00 + 6.2 год = **14:12**.
6. Число йде в нотатку плану, у таблицю днів.

**«Ніч −6.3 °C на ночівлі w30» (старт 23.11, recorded 14.11):** Open-Meteo дає мінімум **−13.4 °C** на найвищій точці маршруту (2007 м) на ранок 24.11 (файл `fixtures/open-meteo/r8613349_2026-11-14.json`, поле `temperature_2m_min`). Ночівля w30 на 920 м, тобто на 1.087 км нижче. Поправка: 6.5 °C × 1.087 = +7.1 °C. Отже −13.4 + 7.1 = **−6.3 °C** (`weather.py`, `LAPSE_C_PER_KM`). Після нового запису прогнозів числа будуть інші, але формула та сама.

### Побічні ефекти
| Що | Ефект |
|---|---|
| `vault_write` | створює або перезаписує `Плани/<запит> — план.md` |
| `vault_append` | дописує рядок зі статусом і посиланням у нотатку-запит |
| `vault_read`, `vault_list` | немає |
| 4 інструменти `plast-trail` | немає (лише читання локальних даних) |
| `assess_weather_risk` у `live`/`record` | мережевий запит до Open-Meteo; `record` ще й пише файл у `fixtures/` |

### Ймовірні питання
| Питання | Відповідь |
|---|---|
| Чим MCP відрізняється від function calling? | Function calling — це коли модель просить викликати функцію. MCP — стандарт, як ці функції віддає окремий сервер: `initialize` → `tools/list` → `tools/call` через JSON-RPC. Модель MCP не бачить: хост перетворює інструменти MCP на схеми для моделі (лекція 4). **У моєму проєкті** хост — це мій код: він сам вирішує, який інструмент викликати, а модель отримує результати й ухвалює рішення про план. |
| Чому модель сама не викликає інструменти? | Свідоме рішення: безкоштовна модель повільна й має ліміт 50 запитів на день, а фіксований порядок гарантує, що перевірку й погоду не пропустять. Модель вирішує те, що потребує розуміння: розбір запиту, вибір маршруту, ночівель і дати. Код перевіряє кожну її пропозицію ще до виклику інструмента. Наступний крок — дати моделі викликати `validate_hike_plan` і `assess_weather_risk` самій. |
| Чому сервер окремим процесом, а не функції в агенті? | Вимога завдання, плюс ці ж інструменти можна підключити до Claude Desktop або до майбутнього сайту для пластунів без копіювання коду. Видно в окремому терміналі й на окремому порту. |
| Чому LangGraph-воркфлоу, а не вільний агент? | Безкоштовна модель повільна (~30 с на виклик) і має ліміт 50 запитів на день. Фіксований порядок дає 3–6 викликів на прогін і не дозволяє пропустити перевірку. Модель вирішує всередині кроків: розбір запиту, вибір плану, висновок. |
| Що, як модель дасть неіснуючий id? | Сервер поверне `WAYPOINT_NOT_FOUND` з підказкою, агент запише це як зворотний зв'язок і попросить новий план. Максимум 4 спроби, потім чесний статус `failed`. |
| Звідки норми? | `data/rules.yaml`: у кожного значення є джерело й `approved: false`. Дослідження на 51 джерело лежить у `research/`. Статус DRAFT видно в кожній відповіді, поки провідник не затвердить. |
| Як відрізнити помилку від порожнього результату? | Помилка: `isError: true` і JSON з `code`/`message`/`hint`. Порожньо: нормальна відповідь `routes: []` з поясненням. |
| Ліміти API? | Open-Meteo: щонайменше 1 с між запитами, кеш 30 хв, повний запис ~121 запит на день із 10 000. OpenTopoData: 100 точок на запит, 1 запит/с. OpenRouter: 3–6 запитів на прогін. |
| Що, як прогнозу на дату немає? | У replay: `WEATHER_FIXTURE_MISSING` зі списком записаних діапазонів; агент позначає погоду як невідому, і план отримує статус `risky`. У live: `DATE_OUT_OF_RANGE`, якщо дата поза 16 днями. |
| Обмеження? | `docs/design-rationale.md`, розділ 7: OSM-дані, маршрут в один бік, погода в одній точці, чернетка норм, безкоштовна модель. |

## 3. Якщо щось пішло не так

| Проблема | Що робити |
|---|---|
| OpenRouter довго думає або повертає 429 | Агент напише «Модель недоступна: … ліміт запитів вичерпано». Ліміт спільний для всіх безкоштовних моделей, тож інша `:free` модель не допоможе; варіанти — почекати, платна модель (`OPENROUTER_MODEL=anthropic/claude-haiku-5.5`, потрібен кредит) або один раз поповнити $10 (ліміт стає 1000/день). |
| `plast-trail is not reachable` | Термінал 1: `uv run plast-trail`. Якщо порт зайнятий: `--port 8771` і `PLAST_TRAIL_PORT=8771` для агента |
| Сертифікат Obsidian | `curl -sk https://127.0.0.1:27124/obsidian-local-rest-api.crt -o certs/obsidian-local-rest-api.crt` |
| Погода `WEATHER_FIXTURE_MISSING` | Дата поза записаним вікном: зміни дату в запиті або `uv run python scripts/record_weather.py` |
| Агент дав `risky` | Це теж валідний результат: показати, що він чесно не рекомендує план, і розібрати причину в нотатці |
