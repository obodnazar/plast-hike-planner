# plast-trail: tool contracts

Generated by `scripts/gen_docs.py` from the live server's `tools/list` on 2026-11-16. Names, model-facing descriptions and schemas below are exactly what an MCP client receives; the example outputs are real calls (lists shortened with `... N more`).

## Server

- **Process:** separate, started with `uv run plast-trail` (streamable HTTP, `http://127.0.0.1:8770/mcp`; `--stdio` also available).
- **Data:** `data/routes.json` (121 OSM routes + SRTM heights), `data/places.json` (1494 named places, the gazetteer), `data/rules.yaml` (norms with sources, approved for the project 16.11.2026), Open-Meteo forecasts (`WEATHER_MODE` live / replay; recording is `scripts/record_weather.py`).
- **Server instructions** (sent at `initialize`) describe the typical flow: resolve place names → find → validate (loop) → weather (loop) → supplies → (optional) route profile for a picture.

Discovered tools: `find_routes`, `resolve_places`, `validate_hike_plan`, `assess_weather_risk`, `calculate_supplies`, `get_route_profile`.

## Error model (all tools)

| Situation | What the caller gets |
|---|---|
| Domain failure (unknown route, missing fixture, …) | `isError: true`; text = `Error executing tool <name>: ` (prefix added by FastMCP) + `{"error": {"code": "...", "message": "...", "hint": "..."}}`. The hint says what the caller (model) should do next |
| Arguments violate the input schema (wrong type, out of range, bad pattern, unknown argument or unknown field inside `group_limits`) | `isError: true`; the same JSON shape with code `INVALID_INPUT` and the failing fields in the message; the tool body never runs. Every input schema has `additionalProperties: false`; only the items of `calculate_supplies.day_loads` accept extra fields, so `validate_hike_plan` `days[]` can be passed as they are |
| Unexpected bug | `isError: true`; code `INTERNAL_ERROR`; stack trace only in the server log |
| Valid request, nothing found / plan breaks rules | **success** with an empty list (`routes: []`) or `valid: false` + `violations` |

Codes: `ROUTE_NOT_FOUND`, `WAYPOINT_NOT_FOUND`, `WAYPOINT_ORDER`, `INVALID_INPUT`, `DATE_OUT_OF_RANGE`, `WEATHER_UNAVAILABLE`, `WEATHER_FIXTURE_MISSING`, `DATA_UNAVAILABLE`, `INTERNAL_ERROR`.

## `find_routes`

| Contract element | Content |
|---|---|
| Name | `find_routes` (title: Find routes for a Plast group) |
| Purpose | First step of planning. Narrows 121 marked Carpathian routes (OpenStreetMap) to the few that fit the group: section, number of days, region, wished features. Ranks them by how well km/day fits the section's target and lists, for each route, the night spots this section may use (waypoint ids). The agent calls it once per run (again with relaxed wishes if nothing matched). |
| Processing | Filters by region and features; drops routes longer than days × daily hard limit or shorter than 3 km/day; requires at least days-1 allowed night spots (новацтво: only huts/campsites); deduplicates night spots per 0.5 km and flags water within 300 m; scores fit = 1 - \|km/day - target\| / target. |
| Side effects | None. Reads `data/routes.json` and `data/rules.yaml` (cached in memory). No network. |
| Annotations | readOnly=True, idempotent=True, openWorld=False |

**Model-facing description (exact):**

> Find marked hiking routes in the Ukrainian Carpathians (OpenStreetMap) that suit a Plast group: age section, number of days, optional region and wished features (lake, peak, ...). Returns routes ranked by how well km/day fits the section's target, each with allowed overnight spots (waypoint ids for validate_hike_plan). Use it first. An empty `routes` list means nothing matched (see `excluded` for why); it is not an error. Not a free-text search; to check or correct a place name first, use resolve_places. Only the bundled Carpathian dataset. Route ids are 'r' + the OpenStreetMap relation id; waypoint ids ('w12') are valid only within their own route.

## `resolve_places`

| Contract element | Content |
|---|---|
| Name | `resolve_places` (title: Resolve place names) |
| Purpose | Understands place names as people write them. A leader writes «піпівана» or «на Говерлу»; this tool finds the named place in a gazetteer of ~1500 OSM peaks, lakes, villages, polonyny and huts, says how sure it is (found / corrected / ambiguous / not_found), which region it is in and how many routes pass it. The agent calls it right after reading the request: corrected names go to find_routes, the places' region fills a missing region, and a place on no route is told to the leader. |
| Processing | 1) the find_routes rule: every word stem of the written name occurs in the place's name; 2) otherwise letter similarity (difflib ≥ 0.8), also against the start of a long name. Ties: the requested region, then peaks and lakes, then places on some route, then the higher peak. on_routes uses find_routes' own matching, so a corrected name is guaranteed to work there. |
| Side effects | None. Reads `data/places.json` and `data/routes.json` (cached in memory). No network. |
| Annotations | readOnly=True, idempotent=True, openWorld=False |

**Model-facing description (exact):**

> Look up peaks, lakes, villages, polonyny or huts by the names people write, including misspellings and case forms ('піпівана' -> 'Піп Іван Чорногірський', 'Говерлу' -> 'Говерла'), in a gazetteer of ~1500 named places from OpenStreetMap. For each name: status found / corrected / ambiguous / not_found, the best place with its kind, region and height, how many routes of the dataset pass it (on_routes = 0: no route passes it, find_routes then ranks routes by their distance to it), and alternatives. Use it before find_routes when a request names places: pass best.name on to find_routes(places=...); when the status is ambiguous, ask the user or take best and tell the user which place was taken; take the region from the places if the request gives none. not_found is a normal result, not an error. Not a route search and not a geocoder outside the Ukrainian Carpathians.

**Input schema**

| Field | Type | Required | Constraints | Default | Description |
|---|---|---|---|---|---|
| `names` | array of string | yes | min items `1`, max items `5`, items: min len `2`, max len `60` | — | Place names as written by the user, e.g. ['піпівана', 'Говерлу'] |

## `validate_hike_plan`

| Contract element | Content |
|---|---|
| Name | `validate_hike_plan` (title: Validate a hike plan) |
| Purpose | The rule checker and the engine of the feedback loop. Given a route and the night spots, it splits the route into days and computes every number itself (km, ascent, walking hours, arrival vs sunset), then checks Plast rules and the group's own limits. Each violation carries a concrete fix, often a better waypoint id, which the agent feeds back to the model. Called after every proposal until valid=true. |
| Processing | Profile slicing between waypoint km; ascent with 10 m hysteresis; walking time by Langmuir's group rule (4 km/h + 1 h per 450 m) + 20 % rests; NOAA sunset at the day's end point (Europe/Kyiv); rules: km/day, walking hours, ascent, allowed night-spot kind, water within 300 m, ridge (within 30 m of the high point in ±1 km), min adults, adult ratio, group size, max days, arrival ≥3 h before sunset. Group limits from Obsidian override rules only when stricter. |
| Side effects | None. Pure computation over the local dataset and rules. |
| Annotations | readOnly=True, idempotent=True, openWorld=False |

**Model-facing description (exact):**

> Check a concrete hike plan against Plast safety rules and the group's own limits. A plan is route_id + the waypoint ids where the group sleeps, in route order (N ids = N+1 days). Computes per-day km, ascent, walking time and arrival vs sunset, checks night spots (allowed kind, water, ridge), number of adults and group size. Returns valid=false with violations; each violation has a concrete suggestion, often a better waypoint id. Re-validate after every change until valid=true. Use only a route_id from find_routes and night spots from its overnight_options; never invent ids. Warnings do not make valid=false but must be reported to the user together with rules_status. The number of night spots fixes the number of days: do not add nights without the user's consent.

| Field | Type | Required | Constraints | Default | Description |
|---|---|---|---|---|---|
| `route_id` | string | yes | pattern `^r\d+$` | — | Route id from find_routes, e.g. 'r8613349' |
| `section` | enum: `novatstvo` / `yunatstvo` / `senior` | yes | — | — | Plast age section of the participants |
| `participants` | integer | yes | ≥ `1`, ≤ `60` | — | Participants of the section (children/youth; for senior: members) |
| `adults` | integer | yes | ≥ `0`, ≤ `30` | — | Adult leaders accompanying the group |

| `start_date` | string (date) \| null | no | — | `null` | First day, YYYY-MM-DD; enables the sunset check |
| `start_time` | string \| null | no | pattern `^([01]\d\|2[0-3]):[0-5]\d$` | `null` | Daily start time HH:MM (24 h), default from rules (08:00) |

## `assess_weather_risk`

| Contract element | Content |
|---|---|
| Name | `assess_weather_risk` (title: Assess weather risk for a plan) |
| Purpose | Turns a forecast into decisions. For the same plan (route + night spots) and a start date it returns a risk level per day with the triggers and what to do. A HIGH result sends the agent back to re-plan (other dates or route); the agent also uses it to probe alternative start dates. |
| Processing | Forecast is taken at the route's highest point (lat, lon, elevation) from Open-Meteo, 16 days. A day is 'exposed' if it reaches above the tree line (1400 m). ## `calculate_supplies`

| Contract element | Content |
|---|---|
| Name | `calculate_supplies` (title: Calculate supplies and pack weight) |
| Purpose | Last planning step: what the group must carry. Takes the per-day loads from validate_hike_plan and the coldest night from assess_weather_risk and returns food, water, gas, tents, stoves, pots, first-aid kits and the pack weight against the section's limit. Every coefficient is echoed in `assumptions` with its source, so any number can be traced. |
| Processing | Food = number of days × people × kg/day by section (0.9; новацтво 0.72); water = max(3 l, 1 l camp + 0.5 l per walking hour); +1.5 l per person per dry night; gas 25 g/person/day ×1.5 with frost; 1 stove + 3 pots per 6; 1 first-aid kit per 10; tents by capacity. Pack = food + 1 l water (+ measured base gear); limit = min(9 kg, % of the lightest body weight). No invented base-gear default. |
| Side effects | None. |
| Annotations | readOnly=True, idempotent=True, openWorld=False |

**Model-facing description (exact):**

> Compute food, water, cooking gas, tents, stoves, pots, first-aid kits and pack weights for a validated plan. Call it last. Pass day_loads = one object per day copied from validate_hike_plan days[] (km, ascent_m, walking_hours), dry_nights = validate_hike_plan dry_nights, night_min_c = assess_weather_risk coldest_night_c. Every coefficient used is listed in `assumptions` with its source.

**Input schema**

| Field | Type | Required | Constraints | Default | Description |
|---|---|---|---|---|---|
| `section` | enum: `novatstvo` / `yunatstvo` / `senior` | yes | — | — | Plast age section of the participants |
| `participants` | integer | yes | ≥ `1`, ≤ `60` | — | Participants of the section (same as in validate_hike_plan) |
| `adults` | integer | yes | ≥ `0`, ≤ `30` | — | Adult leaders |
| `day_loads` | array of object `DayLoad` | yes | min items `1`, max items `7` | — | Array with one object per hiking day (NOT a number): km, ascent_m, walking_hours copied from validate_hike_plan days[] |
| `dry_nights` | integer | no | ≥ `0`, ≤ `6` | `0` | validate_hike_plan dry_nights: night spots without water nearby |
| `night_min_c` | number \| null | no | ≥ `-40`, ≤ `30` | `null` | assess_weather_risk coldest_night_c, °C; omit if the weather was not assessed |
| `tent_capacity` | enum: `2` / `3` / `4` | no | — | `3` | People per tent |
| `lightest_body_weight_kg` | number \| null | no | ≥ `15`, ≤ `150` | `null` | Body weight of the lightest participant, for the % body-weight pack rule |
| `participant_base_gear_kg` | number \| null | no | ≥ `1`, ≤ `25` | `null` | Measured weight of a participant's packed rucksack without food and water |
| `adult_base_gear_kg` | number \| null | no | ≥ `1`, ≤ `30` | `null` | Same for an adult leader |

`DayLoad`: One day of a validated plan: copy km, ascent_m and walking_hours from a validate_hike_plan days[] entry.

| Field | Type | Required | Constraints | Default |
|---|---|---|---|---|
| `km` | number | yes | ≥ `0`, ≤ `40` | — |
| `ascent_m` | integer | yes | ≥ `0`, ≤ `3000` | — |
| `walking_hours` | number | yes | ≥ `0`, ≤ `16` | — |

**Output schema** (`structuredContent`; the same JSON is also sent as text)

| Field | Type | Meaning |
|---|---|---|
| `people` | integer | Participants + adults |
| `num_days` | integer | Number of hiking days |
| `kcal_per_person_day` | integer | Energy target for a participant of this section |
| `food_kg_per_person` | number | Food per participant for the whole hike, kg |
| `food_kg_group` | number | Food for the whole group, kg |
| `water_l_per_person_by_day` | array of number | Water need per person for each day, l |
| `water_to_carry_for_dry_nights_l` | number | Extra water for nights without a source, whole group, l |
| `gas_g_group` | number | Cooking gas for the whole hike, g |
| `stoves` | integer | Stoves (one per kitchen group) |
| `pots` | integer | Pots of at least 3 l |
| `tents` | integer | Tents of the given capacity |
| `first_aid_kits` | integer | Group first-aid kits |
| `pack_participant` | object `PackEstimate` | Start-of-hike pack of a participant |
| `pack_adult` | object `PackEstimate` | Start-of-hike pack of an adult leader |
| `gear_additions` | array of string | Extra gear for this plan (Ukrainian): cold nights, dry nights, long days |
| `warnings` | array of string | Problems to solve before the hike (Ukrainian, for the leader) |

| Field | Type | Meaning |
|---|---|---|
| `name` | string | Key in rules.yaml `supplies` |
| `value` | number \| string | Value used |
| `source` | string | Where the value comes from |

</details>

<details><summary><code>PackEstimate</code></summary>

| Field | Type | Meaning |
|---|---|---|
| `personal_gear_kg` | number \| null | Measured base gear without food and water; null if not given |
| `food_kg` | number | Food for the whole hike, carried at the start |
| `water_kg` | number | Water carried on the heaviest day: the flask, plus dry-night water if any night has no source |
| `total_kg` | number | Peak weight: all food + carried water (+ personal gear if given) |
| `limit_kg` | number \| null | Strictest applicable limit: kg rule and % of body weight |

| `remaining_for_gear_kg` | number \| null | Limit minus food and water: what is left for all other gear |
| `within_limit` | boolean \| null | Null when the limit or the gear weight is unknown |

</details>

**Error conditions**

| Condition | Representation |
|---|---|
| Schema violations (empty `day_loads`, >7 days, km > 40, tent_capacity not 2/3/4) | `isError: true`, pydantic message |
| `dry_nights` larger than the number of nights | code `INVALID_INPUT` |
| A coefficient missing in rules.yaml | code `DATA_UNAVAILABLE`, names the missing key |
